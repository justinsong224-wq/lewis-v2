## ① 展示 Lewis，介绍选题与技术栈

**位置：A，Lewis 开发工作台。** 指需求输入框和办公室角色。

> 我的毕业设计是面向软件开发场景的多智能体协作系统 Lewis。用户提出需求后，系统组织不同角色完成分析、调研、规划、开发、测试和交付，并保存过程证据。

> 前端使用 Vue 3 和 Pinia；后端使用 FastAPI；LangGraph 组织协作流程；MCP 执行文件、搜索和测试工具；SQLite 保存任务与日志，WebSocket 更新页面状态。

只介绍用途和结构，先不提交需求、不点动画。

## ③ 播放协作流程，讲清 Agent 做了什么

**回到 B。** 先展开任务详情看角色说明；重点打开 Search 的“查看调研报告”，指出搜索结论与参考来源，然后关闭报告页。

模型选型对比点“Search 模型对比补充调研”：这是本轮真实调用 Search Agent 新增的报告，原始调研主要针对页面和接口。报告比较字符 TF-IDF + 逻辑回归与中文 Transformer；同划分测试中 baseline F1 为97.60%，Transformer 为97.14%，如实说明 baseline 略高。

需要展示具体分工时，展开“查看需求、方案和审查详情”：点“需求与验收条件”看 PM 的需求整理；点“方案与执行计划”看 CEO 的任务分工。基础任务属于修复任务，这里的原始需求与方案沿用父任务，页面会注明。看完收起即可。

> 这边我现场演示一下 Lewis 的协作运行流程。这里用32秒预设动画讲解，实际开发证据是刚才展示的历史任务。

收起任务详情 → 办公室顶部点“演示协作全流程”。不用填写或提交需求。

先指 CEO 技术总监概括分工，再随亮起角色讲解。**职责可从上往下介绍，实际运行顺序是 PM → Search → CEO → 开发 → 测试 → 文档 → 审查 → 交付。**

| 角色 | 简短讲解 |
|---|---|
| CEO · 技术总监 | 制定技术方案，拆分任务并安排依赖和角色分工。 |
| PM · 项目经理 | 整理用户需求、功能范围和验收条件。 |
| Search · 技术调研 | 搜索技术资料，形成刚才打开的调研报告，供技术规划参考。 |
| Dev · 开发 | 读取已有代码，通过 MCP 修改接口和页面。 |
| Test · 测试 | 编写并真正执行测试，保存命令、输出和结果。 |
| Writer · 文档 | 整理 README 的启动、功能和限制。 |
| Review · 审查 | 阅读实际代码，检查需求覆盖并记录问题。 |
| Customer · 交付 | 根据实际产物与验证结果整理交付说明。 |

动画32秒自动走完。报告在动画前打开讲解，不必赶着32秒内阅读；动画中按角色各讲一句即可。动画不调用模型、不产生新文件，也不是历史日志回放。
